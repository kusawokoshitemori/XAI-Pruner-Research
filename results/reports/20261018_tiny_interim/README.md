# XAI-Prunerの公開実装を用いたDeiT-Tiny枝刈り・学習の中間報告

記録日：2026年10月18日。**epoch 60終了時点（0始まり、検証記録61件／予定300 epoch）**の固定スナップショット。実行中ログは後で更新されるため、以下の結論はこの時点に限定する。

## 1. 目的と、今回まだ証明していないこと

目的は、公開実装のNaNを含む挙動を修復せず観測し、ログ追加が計算結果を変えていないか確認したうえで、論文の報告値との対応を調べることである。数値安定化手法の改善実験とは区別する。

今回の1実行だけでは、(a) 元公開コードとログ付きコードの全処理の一致、(b) 論文条件の完全な一致、(c) 300 epoch後の最終精度、のいずれも証明していない。現在の数値は中間結果として報告する。NaNの発生は今回の観測対象であり、検出だけを理由に実行を修正・停止していない。

対象論文：Di Niuほか、XAI-Pruner: Explainability-Driven Pruning of CNN and Transformer、ICASSP 2026、DOI: 10.1109/ICASSP55912.2026.11462953。論文PDFの3.1節・Table 1（PDF第3ページ）を参照。元コード：[Gyuuteki/XAI-Pruner](https://github.com/Gyuuteki/XAI-Pruner)、比較に使ったローカル取得版commit `45421da8e7a1ec4a93ac2d8284e4ae1152fae9a2`。研究用コード：[kusawokoshitemori/XAI-Pruner-Research](https://github.com/kusawokoshitemori/XAI-Pruner-Research)。ローカルPDFの再配布は本資料に含めない。

## 5. データと前処理

train：1,281,167画像・1,000クラス。val：50,000画像・1,000クラス・各50枚。subImageNet：100,000画像・1,000クラス。関連度計算ログは782バッチ・100,000画像を記録。クラス名とデータ順・画像hashを元ログで追跡可能だが、元実装と全件比較した証明ではない。

10/13、val直下に未分類で残っていた13,619枚を分類した。分類済み36,381枚が公開対応表と一致し、全50,000画像のファイル名に欠番・重複がないことを確認したうえで、残りを移動した。以前の36,381枚の評価と今回の50,000枚の評価は母集団が違う。[修復記録](../../../analysis/imagenet_val_repair_20261013.md)参照。画像全件の破損検査・公式archiveのMD5照合まで終えたことを意味しない。

元公開コードの既定IMNET分岐はfolder_nameを使わずvalを読む。今回は既存EVO_IMNET分岐をCLIから選べるようchoicesを追加し、--data_set EVO_IMNETを指定した。これは論文/READMEのsubImageNetの説明に近づけた実験条件であり、**元コードの既定コマンドとログだけ違う実験ではない**。元コードとの同条件比較では双方に同じデータを渡す方法を決め、変更内容を明示する必要がある。

入力224×224、patch16。評価は短辺256へbicubic resize→center crop224→tensor→mean=std=(0.5,0.5,0.5)で正規化（imagenet_default_mean_and_std=False）。学習はRandAugment、Mixup0.8、CutMix1.0、Random Erasing0.25、Label smoothing0.1、drop_path0.1。詳細は[設定](finetune_config.yaml)。

## 6. モデル・枝刈り・訓練の条件

モデルは非蒸留DeiT-Tiny：embed192、12 blocks、各3 heads、MLP hidden768。初期重みはcheckpoint/deit_tiny_patch16_224.pth。ファイルhashは[source_manifest.json](source_manifest.json)に保存。モデル定義には公式DeiTの事前学習URLがあるが、このファイルの公式配布物とのbyte一致、同じval上の未枝刈り精度72.20%の再測定はまだ証明していない。

| 条件 | 今回 |
|---|---|
| EA遺伝子 | dim_rate, hidden_rate, head_rate |
| FLOPs削減目標 / 許容幅 | 0.244 / ±0.0001（連続候補の計算上） |
| population / generation / Top-k | 100 / 100 / 50 |
| protect_rate / filter_percent | 0.25 / 0.5 |
| momentum | 0.9 |
| 関連度計算batch | 128 |
| 詳細LRPログ範囲 | 先頭2バッチ（最大256画像）。LayerNorm健全性等の監視範囲とは異なる |
| 初期関連度 | 予測クラスのsoftmax確率。正解ラベルのクラスを必ず使う処理ではない |
| 学習器 | AdamW、weight_decay0.05、opt_eps1e-8 |
| 学習率 / 下限 / スケジュール | 1e-3 / 1e-5 / cosine |
| warmup / cooldown | 0 / 0 epoch |
| batch / GPU / 総batch | 128 / 1 / 128、勾配蓄積なし |
| AMP / EMA / teacher | True / False / なし |
| seed | torchとNumPy=0。EAのPython randomは未固定 |
| train_one_epoch内Python乱数 | random.seed(epoch)を呼ぶ。前記EAの未固定とは区別 |
| 訓練の読み込みワーカー | train/valともコードで16固定。args.num_workers=10はこの箇所では不使用 |
| サンプラー | 訓練は1-rank DDP + RASampler、検証はSequentialSampler |
| pin_memory | True |

RASamplerは通常の全画像一巡とは異なる繰返し拡張の選択を行う。10008 steps×128=1,281,024学習提示／epochで、固有画像数とは同じでない。コード上1 GPUでは選択された画像を3回ずつ提示する方式。epoch数だけで別のサンプラーと学習量が同じとは言えない。実行時のDataLoader.prefetch_factor既定値、workerの乱数状態、全乱数stateの保存は未収録。

momentumの実装は S_t=0.9*S_(t-1)+s_t（初回は最初のスコア）。手書き資料の0.9*S+(1-0.9)*sとは係数が違う。単純平均と違って後半バッチを強く重み付けするが、それだけで性能悪化や不正確な重要度を証明しない。NaNはこの更新を通じて残る。

## 9. NaNとEAの、今回の実測

新規dimスコアがNaNとなったbatchは87/117/167/205/211/491/500/655/705。最終dim192個は全NaN、head/hiddenの保護前スコアは全有限。保護後の各層headのInfは保護用の意図した値で、異常なNaNと区別する。元ログのLayerNormゼロ観測等は[facts.json](facts.json)を参照。

全10,019候補評価行のFitnessがNaN。これは世代ごとの行数で、10,019種類の固有モデルではない。np.argsort(fitness)で選択を続けており、有限Fitnessに基づく優劣を評価できない。**「ランダムサーチと等価」とは言わない**。NaNで返るsort順には列挙順・NumPy実装等が関与し、正規のランダム探索とは異なる。

| 今回の演算子 | 試行数 | 制約通過（修正前） | 親プールにない候補の追加 | 新規削除数マスクの追加 |
|---|---:|---:|---:|---:|
| 交叉 | 10,000 | 2,517 | 11 | 0 |
| 突然変異 | 10,000 | 4,184 | 8 | 5 |

突然変異で0遺伝子変更は4,176/10,000=41.76%、1遺伝子変更は4,221/10,000=42.21%。新規性はCSVのnovel_*_addedの定義。親とは直接の2親だけでなくその世代の親プール。mask IDは削除数由来であり、任意の実テンソルマスクのhashと同義ではない。同一スコア・固定順位という前提が必要。元の10/1実行では新規候補5/14・新規マスク0/9だったため、今回の数値と混ぜない。

元リポジトリ取得版のrules.pyと、研究リポジトリ初期取り込み版のrules.pyのSHA-256は一致（3148b9c48684cb2199488d36f0432bfe42e36ae7a927d9adf4b183b2c6a714ca）。10/17の試験に加え、10/18にも同一入力のCPU局所試験を実施し、両方で_stabilize(0)=0、LayerNorm返却関連度24/24がNaN（[試験条件と結果](upstream_local_check.json)）。これは元コードにも同じ発生機序があることの証拠であり、全実画像での一致を証明するものではない。既存の局所観測専用テスト3件も通過しているが、比較参照は編集履歴から復元したもので、全モデルの元コード対照とは区別する。

## 14. 推奨する最終レポート構成と結論文

構成は、目的→論文/公開実装の条件→環境/データ/変更点→実行ごとの結果→数値異常と探索の観測→解釈と代替説明→限界と次の検証→再現資料、の順にすると読み手が判断しやすい。

結論文案：

> 公開実装の計算規則を修復せず診断ログを追加したDeiT-Tiny実験において、embedding dimensionの累積関連度192個すべてと候補評価10,019行すべてのFitnessがNaNとなった。一方、構築された枝刈りモデルのfine-tuningは継続しており、61回の検証を終えた時点の最高Top-1は38.92%であった。論文の報告値70.99%は300 epoch訓練後の値であり、本中間結果だけから再現の成否は判断できない。また、公開コードの既定動作とのデータ選択の差、ソフトウェア環境差、枝刈り後構造の差、ログ追加前後の全処理一致が未検証である点が残る。NaNの発生は元コードと研究用コードの局所試験でともに確認されたが、全実行での一致や精度低下の原因を確定するには同条件対照が必要である。
